# タスクボードアプリケーション 要件定義書

> 関連Issue: #3
> 本書は [CLAUDE.md](../CLAUDE.md) の「アプリケーション概要」を詳細化したものです。後続の実装Issueは本書を参照して着手してください。

## 1. 概要

未着手 / 進行中 / 完了 の3列で構成されるシンプルなカンバン型タスク管理アプリ。タスクを作成し、列間をドラッグ&ドロップで移動させることでステータスを管理する。

- 利用者は1名(認証なし)、ボードは1つのみ。
- データはブラウザの localStorage に保存し、リロード後も保持する。

## 2. 画面構成・レイアウト

### 2.1 画面構成

画面は1ページ(`/`)のみ。

```
┌──────────────────────────────────────────────────────┐
│ ヘッダー: アプリ名                  [+ タスクを追加] │
├──────────────────────────────────────────────────────┤
│ ┌ 未着手 (2) ──┐ ┌ 進行中 (1) ──┐ ┌ 完了 (0) ────┐ │
│ │ ┌──────────┐ │ │ ┌──────────┐ │ │              │ │
│ │ │タイトル  │ │ │ │タイトル  │ │ │ タスクは     │ │
│ │ │説明…     │ │ │ │説明…     │ │ │ ありません   │ │
│ │ └──────────┘ │ │ └──────────┘ │ │              │ │
│ │ ┌──────────┐ │ │              │ │              │ │
│ │ │タイトル  │ │ │              │ │              │ │
│ │ └──────────┘ │ │              │ │              │ │
│ └──────────────┘ └──────────────┘ └──────────────┘ │
└──────────────────────────────────────────────────────┘
```

| 要素 | 内容 |
| --- | --- |
| ヘッダー | アプリ名と「タスクを追加」ボタンを表示する。ボタン押下でタスク追加モーダルを開く。 |
| ボード | 3列を「未着手 → 進行中 → 完了」の順で表示する。 |
| 列ヘッダー | 列名と、その列のタスク件数を表示する(例: `未着手 (3)`)。 |
| 列本体 | 所属するタスクをカード形式で縦に並べる。 |
| タスクカード | タイトルと説明を表示する(詳細は 2.3)。 |

### 2.2 レスポンシブ対応

| 画面幅 | レイアウト |
| --- | --- |
| 768px 以上(Tailwind `md` 以上) | 3列を横に等幅で並べる。 |
| 768px 未満 | 3列を縦に積む(未着手 → 進行中 → 完了 の順)。 |

- いずれの幅でも、ページ全体の横スクロールは発生させない。
- 縦積み時もドラッグ&ドロップで列移動できること(タッチ操作対応。4.3 参照)。

### 2.3 タスクカードの表示

- **タイトル**: 全文を表示する。長い場合は折り返す(省略しない)。改行やスペースなしの長い英数字も枠からはみ出さず折り返す。
- **説明**:
    - 入力された改行を反映して表示する。
    - 3行を超える場合は、3行目の末尾を「…」として省略する(line-clamp)。
    - 説明が空の場合は、説明欄自体を表示しない(空の余白を作らない)。
    - 省略された説明の全文を確認する手段は本スコープでは提供しない(タスク詳細表示・編集はスコープ外のため)。

### 2.4 初期表示・空状態

- 初回アクセス時(保存データなし)は、3列すべてが空の状態で表示する。
- タスクが0件の列には、列本体に「タスクはありません」と表示する。
- 空の列も一定の最低高さを持ち、ドロップ先として操作できること。
- localStorage の読み込みはクライアントでのマウント後に行う(SSR時との不一致を避けるため)。読み込み完了までは列の中身を表示せず、読み込み前に「タスクはありません」が一瞬表示されないようにする。

## 3. データモデル

### 3.1 タスク(Task)

| 項目 | 型 | 必須 | 制約・説明 |
| --- | --- | --- | --- |
| `id` | string | ○ | 一意なID。作成時に `crypto.randomUUID()` で生成する。HTTP でLAN内のアドレス(例: `http://192.168.x.x:3000`)から開いた場合など、`crypto.randomUUID()` が使えない環境では `crypto.getRandomValues()` で生成した乱数から UUID v4 形式の文字列を作る。 |
| `title` | string | ○ | 前後の空白を除去した値。1〜50文字。 |
| `description` | string | ○ | 前後の空白を除去した値。0〜500文字。未入力時は空文字 `""`。 |
| `status` | `"todo"` \| `"in_progress"` \| `"done"` | ○ | 所属する列。作成時は `"todo"`。 |
| `createdAt` | string | ○ | 作成日時(ISO 8601 形式)。 |

- 文字数は見た目の1文字(書記素クラスタ)単位で数える。`Intl.Segmenter`(`granularity: "grapheme"`)で分割した個数を文字数とする。
    - 例: `あ` / `😀` / `👨‍👩‍👧`(ZWJ結合絵文字)/ `🇯🇵`(国旗)/ `が`(`か` + 濁点の結合文字)は、いずれも1文字と数える。
    - 入力欄の文字数カウンター(4.2)とバリデーションは同じ数え方を使う。
- タイトルの重複は許可する。同一タイトルのタスクも `id` で区別する。

### 3.2 ステータスと列の対応

| status | 列名 |
| --- | --- |
| `todo` | 未着手 |
| `in_progress` | 進行中 |
| `done` | 完了 |

### 3.3 状態遷移

- 3つのステータス間は、どの方向にも自由に移動できる(例: 未着手 → 完了、完了 → 未着手 も可)。
- 状態遷移の手段はドラッグ&ドロップのみ。

### 3.4 列内の表示順

- タスクは配列で保持し、配列の順序を表示順とする。
- 新規作成したタスクは「未着手」列の**末尾**に追加する。
- 列を移動したタスクは移動先の列の**末尾**に表示する(実装上は配列から取り除き末尾に追加する)。
- 列内での並び替えはスコープ外。

### 3.5 永続化(localStorage)

- 保存キー: `taskboard:tasks`
- 保存形式:

  ```json
  {
    "version": 1,
    "tasks": [
      {
        "id": "…",
        "title": "…",
        "description": "…",
        "status": "todo",
        "createdAt": "2026-09-24T00:00:00.000Z"
      }
    ]
  }
  ```

- タスクの追加・移動のたびに、全タスクを保存する。
- 起動時に保存データを読み込み、ボードに復元する。

## 4. 機能要件

### 4.1 カンバンボードの表示

- 3列を 2.1 の構成で表示し、各タスクを `status` に対応する列に表示する。
- 列ヘッダーの件数は、タスクの追加・移動に合わせて即座に更新する。

### 4.2 タスクの追加

#### モーダルの開閉

| 操作 | 挙動 |
| --- | --- |
| ヘッダーの「タスクを追加」ボタン押下 | モーダルを開く。入力欄は空の状態で、タイトル欄にフォーカスする。 |
| 「キャンセル」ボタン押下 | モーダルを閉じる。入力内容とエラー表示は破棄する。 |
| 背景(オーバーレイ)クリック | キャンセルと同じ。ただし、マウスボタンを押した位置と離した位置がともに背景上の場合のみ閉じる(入力欄での範囲選択中に背景上でボタンを離しても閉じない)。 |
| Esc キー | 閉じない(対象外)。 |
| 追加成功 | モーダルを閉じる。入力内容は破棄する。 |

- モーダル表示中は背景のボードを操作できない。
- モーダルには `role="dialog"` と `aria-modal="true"` を付与し、見出し(「タスクを追加」)を持たせる。
- モーダル表示中は、Tab / Shift+Tab によるフォーカス移動をモーダル内に閉じ込める(最後の要素から Tab で先頭の要素へ、先頭の要素から Shift+Tab で最後の要素へ循環させる)。
- モーダルを閉じたら(キャンセル・背景クリック・追加成功のいずれでも)、フォーカスを「タスクを追加」ボタンに戻す。

#### 入力項目

| 項目 | 入力形式 | 必須 | 上限 | 備考 |
| --- | --- | --- | --- | --- |
| タイトル | 1行テキスト | ○ | 50文字 | ラベルに必須であることを表示する。 |
| 説明 | 複数行テキスト(textarea) | - | 500文字 | 改行を入力できる。 |

- 各入力欄の下に現在の文字数を `12 / 50` の形式で表示する。上限を超えた場合はカウンターを赤字にする。
- 入力欄の `maxLength` による入力制限はかけない(超過は送信時にエラーとして知らせる)。
- 送信はモーダル内の「追加」ボタン押下、またはタイトル欄での Enter キーで行う。説明欄の Enter は改行とする。
- 日本語入力(IME)で変換中の Enter は変換の確定として扱い、送信しない(`KeyboardEvent.isComposing` が `true`、または `keyCode` が `229` の場合)。

#### バリデーション

送信時に以下を検証する。検証はすべて前後の空白(スペース・タブ・改行)を除去した値に対して行う。

| 対象 | 条件 | エラーメッセージ |
| --- | --- | --- |
| タイトル | 空(空白のみを含む) | タイトルを入力してください |
| タイトル | 51文字以上 | タイトルは50文字以内で入力してください |
| 説明 | 501文字以上 | 説明は500文字以内で入力してください |

- エラーは該当する入力欄の直下に赤字で表示する。複数項目でエラーがあれば、すべて同時に表示する。
- エラーがある場合はタスクを作成せず、モーダルを開いたまま入力内容を保持する。
- エラー表示は再送信時に再検証して更新する(入力中にリアルタイムで検証はしない)。

#### 作成

- 検証を通過したら、3.1 に従ってタスクを作成し、「未着手」列の末尾に追加して保存する。

### 4.3 ドラッグ&ドロップによる列移動

- 実装には `@dnd-kit/core` を使用する。
- 操作方法:
    | 入力 | 操作 |
    | --- | --- |
    | マウス | カードを押したまま一定距離(5px程度)動かすとドラッグを開始する。クリックだけではドラッグしない。 |
    | タッチ | カードを長押し(250ms程度)するとドラッグを開始する。短いタッチやスワイプはページのスクロールとして扱う。 |
    | キーボード | カードにフォーカスしてスペース/Enter で持ち上げ、矢印キーで移動、スペース/Enter で確定、Esc でキャンセル(dnd-kit 標準)。矢印キー1回で隣の列へ移動する(横並び時は ←/→、縦積み時は ↑/↓)。端の列からさらに外側へは移動しない。 |
- ドラッグの対象はタスクカード全体とする。
- ドロップ先の判定: 対象は**列の領域全体**(列ヘッダー・カードの上・空き領域を含む)とし、入力方法ごとに以下で判定する。
    - マウス・タッチ: ポインタが乗っている列。
    - キーボード: ポインタの位置がないため、ドラッグ中のカードが重なっている列(重なっている列が複数ある場合は重なる面積が最も大きい列)。
- ドラッグ中の表示:
    - ドラッグ中のカードはポインタに追従して表示する(キーボード操作時は矢印キーの操作に合わせて移動する)。
    - 元の位置のカードは半透明にする。
    - 上記の判定でドロップ先となる列をハイライトする(背景色や枠線の変化)。
- ドロップ時の挙動:
    | ケース | 挙動 |
    | --- | --- |
    | 別の列にドロップ | タスクの `status` を更新し、移動先の列の末尾に表示、移動元の列から消す。件数を更新して保存する。 |
    | 同じ列にドロップ | 何も変更しない(並び順も変えない)。 |
    | 列の外にドロップ / キャンセル | 何も変更しない。カードは元の位置に戻る。 |

## 5. 異常系・エッジケース

| # | ケース | 挙動 |
| --- | --- | --- |
| 1 | タイトルが空・空白のみ | 必須エラー(4.2)。 |
| 2 | 説明が空 | 許可する。カードでは説明欄を表示しない。 |
| 3 | タイトル・説明が上限超過 | 文字数エラー(4.2)。 |
| 4 | 前後に空白・改行を含む入力 | 除去してから検証・保存する。途中の改行はそのまま保持する。 |
| 5 | 長い単語・URLなどスペースのない長文 | カード内で折り返し、はみ出さない。 |
| 6 | 同一タイトルのタスク | 許可する(`id` で区別)。 |
| 7 | HTMLタグなどを含む入力 | 文字列としてそのまま表示する(React の標準エスケープに任せ、`dangerouslySetInnerHTML` は使わない)。 |
| 8 | localStorage に保存データがない | 空のボードで開始する。 |
| 9 | 保存データ全体が不正(JSONとして読めない、`version` が `1` でない、`tasks` が配列でない) | 空のボードで開始する。エラーは画面に表示せず、コンソールに警告を出す。次の保存時に上書きされる。 |
| 10 | 保存データの一部のタスクだけが不正(下記の判定条件を満たさない) | 不正なタスクだけを除外し、残りのタスクでボードを復元する。除外した件数をコンソールに警告として出す。除外したタスクは次の保存時に失われる。すべてのタスクが不正な場合は空のボードで開始する。 |
| 11 | 保存データ内で `id` が重複している | 配列の先頭に近いタスクを残し、後から出てくる同じ `id` のタスクは不正として除外する(#10 と同じ扱い)。 |
| 12 | localStorage が利用できない(プライベートモード・容量超過などで読み書き時に例外) | 例外を捕捉し、画面の操作は継続できるようにする(その場合リロードで内容は失われる)。コンソールに警告を出す。 |
| 13 | 複数タブで同時に開いた場合 | 同期しない。最後に保存したタブの内容で上書きされる(スコープ外として許容)。 |

保存データ内の各タスクは、以下をすべて満たす場合のみ有効とする(3.1 の制約に準じる)。

- `id`: 空でない文字列
- `title`: 文字列で、前後の空白を除去した値が 1〜50文字
- `description`: 文字列で、前後の空白を除去した値が 0〜500文字
- `status`: `"todo"` / `"in_progress"` / `"done"` のいずれか
- `createdAt`: 日時として解釈できる ISO 8601 形式の文字列

## 6. 非機能要件

- 対応ブラウザ: 最新版の Chrome / Edge / Safari / Firefox(デスクトップ・モバイル)。
- アクセシビリティ: ボタン・入力欄にラベルを付け、キーボードだけでタスクの追加と列移動ができること。
- テスト(Vitest): 以下のロジックはUIから切り離し、ユニットテストの対象とする。
    - 入力値のバリデーション(空・空白のみ・境界値 50/51文字、500/501文字、trim、ZWJ結合絵文字・国旗・結合文字をそれぞれ1文字と数えること)
    - タイトル欄の Enter キーによる送信判定(通常の Enter では送信し、IME 変換中の Enter では送信しない)
    - タスクの作成(初期 `status`・末尾への追加・`crypto.randomUUID()` が使えない環境でも `id` を生成できること)
    - タスクの列移動(`status` 更新・移動先末尾への配置・同一列では変更なし)
    - localStorage からの読み込み・保存(データなし、データ全体が不正、一部のタスクのみ不正、`id` の重複、例外発生時)

## 7. スコープ外

以下は現時点では対応しない。

- ユーザー認証・複数ユーザーでの共有
- 複数ボードの作成・切り替え
- タスクの編集・削除
- タスク詳細の表示(省略された説明の全文表示を含む)
- 期限日・担当者・優先度などの付加属性
- 列内でのタスクの並び替え
- 列の追加・削除・名前変更
- 複数タブ間のデータ同期
- サーバー側へのデータ保存
