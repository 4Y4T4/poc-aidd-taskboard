以下の内容について実行計画を立て、`docs/requirements.md` と `docs/execution-plan.md` に必要な内容を追記して、ブランチにプッシュしてください。

計画したい内容: $ARGUMENTS

## 0. 計画内容の確認

- 上の「計画したい内容」が空の場合は、作業に入らず、チャットで何を計画したいかを質問する。回答を受け取ってから次に進む。

## 1. 現状の把握

- `CLAUDE.md`・`docs/requirements.md`・`docs/execution-plan.md` を読む。
- 計画内容に関係する既存のコード・テストを読み、影響する範囲(変更が必要なファイル、既存の仕様との関係)を洗い出す。
- 計画内容に Issue 番号が含まれている場合は、`gh issue view <番号>` で内容を確認する。
- CLAUDE.md のスコープ外項目に当たる内容が含まれている場合は、その旨を伝えて進め方を確認する。

## 2. 決めるべき点の確認

- 仕様に曖昧な点や、複数の選択肢がある点(例: 表示位置、値の名前、レイアウト、既存データとの互換性)があれば、追記する前に質問して決める。
- 推奨する案がある場合は、理由とあわせて示す。

## 3. 追記内容の了承

- 追記・修正する内容を、ファイルと章ごとに一覧にして示す(例: 「requirements.md 3.2: 対応表に保留を追加」「execution-plan.md 2章: #23 の行を追加」)。
- 了承を得るまで、ファイルの変更・コミット・プッシュはしない。修正の依頼があれば、一覧を直して再度示す。

## 4. ブランチの準備

- 現在のブランチが計画内容の Issue の作業ブランチであれば、そのまま使う。
- `main` にいる場合は、最新の `main` を取り込み、CLAUDE.md の命名規則に従ってブランチを切る(ドキュメントの変更のみなので `doc/#Issue番号`)。Issue 番号が分からない場合は質問する。
- 作業ツリーに未コミットの変更がある場合は、先に内容を確認して報告する。

## 5. 要件定義書(`docs/requirements.md`)への追記

- 既存の章立て・番号・表の形式に合わせて、該当する章に追記または修正する。新しい章を増やすのは、既存の章に収まらない場合だけにする。
- 追記した内容が、既存の記述(画面構成・データモデル・異常系・非機能要件・スコープ外など)と矛盾しないようにする。矛盾する既存の記述は、あわせて修正する。
- 6章のテスト観点に、追加するユニットテストの観点を加える。

## 6. 実行計画(`docs/execution-plan.md`)への追記

- 2章の実装Issue一覧に、作業・担当のサブエージェント(`.claude/agents/` のいずれか)・依存・主な参照章・ユニットテストの観点を追加する。
- 3章の依存関係と着手順序、4章のディレクトリ構成、6章のリスクと対応方針に、必要な内容を追加する。
- 作業が大きい場合は、1つの PR で無理なくレビューできる粒度に分割する。

## 7. コミットとプッシュ

- コードは変更しない(実装は `/implement-issue` で行う)。
- CLAUDE.md のコミットルールに従い、要件定義書と実行計画は別のコミットに分け、`📝` を付ける。
- ブランチをリモートにプッシュする。プルリクエストは作成しない。

## 8. 報告

- 追記・修正した章と内容の要約、決めた点とその理由、実装で注意すべき点を報告する。
- 実装 Issue の起票が必要であれば、その旨を伝える(起票はしない)。
