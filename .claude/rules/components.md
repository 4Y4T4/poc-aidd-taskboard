# コンポーネント・スタイリングのルール

## コンポーネントの分け方

- 責務ごとにコンポーネントを分ける(ボード全体 `Board`・列 `Column`・タスクカード `TaskCard`・追加モーダル `AddTaskModal`・追加フォーム `AddTaskForm` など)。新しく作るときも同じ粒度にし、細かく分けすぎない。
- ドラッグ&ドロップの当たり判定・キーボード操作の座標計算・読み上げ文などは `src/components/dnd/` に、React に依存しない関数として置く。
- 画面に依存しない判定(バリデーション・送信判定など)は `src/lib/` の純粋関数に切り出し、コンポーネントからは呼ぶだけにする。

## 書き方

- コンポーネントは `export function 名前()` で定義し、props の型は直前に `type 名前Props = { … }` として書く。
- ファイル名はコンポーネント名と同じ PascalCase(`TaskCard.tsx`)、フックは `use` で始まる camelCase(`useTasks.ts`)にする。
- `"use client"` はクライアント側の処理の入口(`Board.tsx`)にだけ付け、その子のコンポーネントには付けない。

## タスクのデータ

- タスクの読み込み・追加・移動は `useTasks` を通して行う。コンポーネントから `localStorage` や `src/lib/storage/` を直接呼ばない。
- サーバー描画とハイドレーションで値が食い違わないようにする。
    - 保存データはサーバー側で読めないため、`useTasks` は未読み込み(`isLoaded === false`)を返す。列の件数やタスクは読み込み後にだけ表示する。
    - ライブラリが自動で採番する id(dnd-kit の `DndContext` など)は、固定の `id` を渡す。

## スタイリング

- スタイルは Tailwind CSS のユーティリティクラスで `className` に書く。`globals.css` 以外の CSS ファイルを作らない。
- 状態による見た目の切り替えは、`aria-invalid:`・`data-over:` のように属性のバリアントで書き、状態を表す属性とスタイルを一致させる。
- フォーカスの見た目は `focus-visible:outline-*` で付ける。
- 4列は 1024px 以上(`lg`)で横に並べ、それ未満は縦に積む。どの画面幅でもページ全体に横スクロールを出さない。
- 長い文字列は `wrap-anywhere` で折り返し、カードからはみ出させない。

## アクセシビリティ

- ボタン・入力欄にはラベルを付ける。ラベルと入力欄・エラー文の対応は `useId` で作った id と `htmlFor`・`aria-describedby` で結ぶ。
- エラー文は `role="alert"` で読み上げる。
- マウスだけでなく、キーボードとタッチでもタスクの追加と列移動ができるようにする。
- フォーカスを移す前に DOM の更新が必要な場合(`inert` が外れる、`aria-describedby` の参照先が追加されるなど)は、`flushSync` で先に反映してからフォーカスを移す。
